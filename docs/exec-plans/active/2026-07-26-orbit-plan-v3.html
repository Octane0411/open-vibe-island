Plan v3: Unified Agent Attention, Approvals & Headroom

A source-backed plan for one calm native macOS companion that unifies cross-agent approvals and denials, active work, provider usage, and context evidence through a Vibe Island-quality notch experience built on Open Island’s GPLv3 foundation.

Active goal
Design, implement, and verify a polished notch flow in which users can safely approve or deny requests across supported agents, identify the active task and required action, and understand trustworthy usage and context headroom within two seconds—without exposing sensitive content or replacing each agent’s enforcement authority.

1. Product definition

Implementation base

Open Island GPLv3 supplies the preserved code history, native SwiftUI/AppKit app, hooks, session discovery, approval/question round trips, terminal jump-back, usage snapshots, settings, and deterministic harness.

Interaction target

Vibe Island defines observable goals for notch fit, morph continuity, hierarchy, timing, density, and polish. Orbit independently implements those goals with its own identity.

Usage capability

CodexBar-style visibility means provider-neutral allowance, pressure, reset, freshness, and availability—not copied assets or assumptions that every provider exposes the same fields.

Context capability

Headroom-style evidence means metadata-only context budgets, retained/omitted token estimates, compaction events, confidence, and redaction boundaries. It does not mean fabricated cost savings.

North-star user outcome

A developer glances at the notch and knows: who is working, on what, whether attention is needed, how constrained usage is, and how healthy context is. Expansion reveals evidence and safe actions, not a miniature analytics dashboard.

3. Resolved product decisions

Workflow routing decision

Using the Ask Matt decision tree and source-backed planning workflow, this is classified as an existing-codebase, multi-phase build: inspect current behavior → resolve decisions against the docs → write a durable plan/ADR/glossary → implement bounded slices → verify after every slice. A throwaway prototype is optional only if motion cannot be settled in the deterministic harness.

  • Active agent first. The compact pill answers “what needs attention?” before showing metrics.
  • Secondary usage/context signal. Show at most one compact pressure indicator; reveal detail when expanded.
  • One primary session. Secondary sessions live behind deliberate disclosure.
  • Deterministic priority. Approval/question → error → active work → unread completion → idle.
  • Truth before completeness. Every metric is live inferred stale or unavailable.
  • Evidence, not marketing. Report estimated tokens retained/omitted and confidence. Dollars require authoritative counts and versioned pricing.
  • Fail open. Missing metrics or Orbit failure never changes the originating agent.

  • Top-anchored matched geometry remains the shell primitive.
  • Ordinary state changes: 160–240 ms. Open/close spring: 280–420 ms.

5. Unified approval and denial broker

Core decision

Orbit owns normalization, prioritization, presentation, user decision capture, delivery status, and immutable receipts. The originating adapter and agent retain enforcement authority. Orbit never invents broader permission semantics than the source supports and never treats a displayed decision as enforced until the adapter acknowledges it.

Existing foundation to preserve

Plan v3 extends, rather than replaces, AgentEvent.PermissionRequested, PermissionRequest, PermissionResolution, BridgeCommand.resolvePermission, and the existing pending Codex, Claude, and OpenCode interaction paths in BridgeServer. Provider-specific semantics stay at each adapter boundary.

Unified inbox

Multiple simultaneous requests are sorted by creation time, expiry, risk, and active-session relevance. One request is primary; the rest remain visible and cannot be overwritten by a newer event.

Least privilege

Allow once is the primary positive action. Session or time-bounded grants appear only when the source explicitly supports them. Orbit never promotes a one-time request to global permission.

Safe denial

Deny is always available, keyboard reachable, and explicit. Timeout, cancellation, stale correlation, missing source, or delivery failure never becomes allow.

Verified outcome

The UI distinguishes decision captured, delivered, acknowledged, rejected, expired, and source unavailable. Duplicate clicks are idempotent and stale buttons cannot resolve a reused request.

Required request content

  • Originating agent, adapter, project, and session
  • Requested capability and redacted target/resource
  • Scope and duration: once, session, or bounded time
  • Reason and concise consequence summary
  • Creation time, expiry, truth state, and correlation ID
  • Exact provider limitations when Orbit cannot respond natively

T3 Code disposition

Optional adapter investigation only. Orbit may integrate with T3 Code if a public, documented hook, extension API, IPC protocol, CLI callback, or event surface and compatible license are verified. No undocumented reverse engineering, T3-specific dependency, or compatibility claim is allowed. Orbit's native broker must work without T3 Code.

6. Data contracts

Provider-neutral approval request

struct OrbitApprovalRequest {
  id: UUID
  correlationID: String
  sessionID: String
  agentID: String
  adapterID: String
  projectLabel: String?
  capability: String
  redactedTarget: String?
  scope: once | session | until(Date)
  reason: String
  consequenceSummary: String
  createdAt: Date
  expiresAt: Date?
  truth: live | inferred | stale | unavailable
}

Decision and delivery

struct OrbitApprovalDecision {
  requestID: UUID
  decisionID: UUID
  outcome: allow | deny | timeout | cancel
  scope: once | session | until(Date)
  decidedAt: Date
  origin: orbitUser | adapter | timeout
  delivery: captured | delivered | acknowledged | rejected | expired
  receiptID: UUID
}

Rule: request and decision IDs are immutable; adapter delivery is idempotent; acknowledgement is recorded separately from user intent; receipts contain only allowlisted metadata.

Provider-neutral usage snapshot

struct OrbitUsageSnapshot {
  providerID: String
  accountScope: String?          // redacted display label only
  observedAt: Date
  period: session | daily | weekly | monthly | unknown
  usedFraction: Double?
  remainingFraction: Double?
  resetAt: Date?
  inputTokens: Int?
  outputTokens: Int?
  estimatedCost: Decimal?
  currency: String?
  truth: live | inferred | stale | unavailable
  source: hook | localFile | providerAPI | process | unavailable
}

Rule: optional fields remain absent. No adapter converts missing data to zero. Orbit does not collect or display provider credentials.

Context evidence event

struct OrbitContextEvidence {
  eventID: UUID
  sessionID: String
  observedAt: Date
  inputTokens: Int
  retainedTokens: Int
  omittedTokens: Int
  decision: withinBudget | needsCompaction | redactionRequired
  confidence: measured | estimated | unavailable
  provenanceID: String
  containsContent: false
}

Presentation projection

A pure projector combines session phase, provenance, usage pressure, context pressure, unread completion, and truth state into one OrbitPrimarySurfaceState. Views do not independently decide priority.

7. Architecture and ownership

Layer 1 · Existing adapters

Hooks, pending approval interactions, transcript registries, process discovery, terminal targeting, and usage monitors. Adapters translate source semantics and retain enforcement authority.

Layer 2 · Normalization

Approval request/decision contracts, OrbitUsageSnapshot, context evidence, provenance, truth/freshness, and attention arbitration. Pure logic lives in OpenIslandCore where possible.

Layer 3 · AppModel projection

One state owner exposes a stable primary surface, secondary metrics, actions, and accessibility labels.

Layer 4 · Native surface

One panel controller and one SwiftUI shell render compact, expanded, notification, reduced-motion, and degraded states.

Ownership invariants

  • One app, one process, one panel controller, one AppModel state owner.
  • Orbit owns the approval inbox and audit trail, but not provider enforcement or hidden policy.
  • Adapters never add independent windows, routers, agent loops, credential stores, or global approval policy.
  • Actions round-trip through the originating adapter only and require acknowledgement.
  • Usage/context polling is bounded, cached, cancelable, and invisible when unsupported.
  • Reference projects remain segregated by license and provenance.

8. Threat and trust model

Protected assets

Credentials, provider tokens, prompts, transcripts, commands, file contents, private paths/endpoints, terminal automation authority, approval decisions, and local usage history.

Trust boundaries

Agent hooks → local socket; transcripts/configs → registries; provider data → usage adapter; AppModel → UI; UI action → originating adapter; deterministic fixtures → screenshots.

9. Accessibility contract

Perceivable

4.5:1 text contrast, 3:1 large/non-text contrast, explicit labels and symbols, no color-only state.

Operable

Keyboard parity, logical focus, visible focus, Escape semantics, 44×44 point targets or equivalent hit regions.

Robust

VoiceOver name/role/value for agent, task, state, metric truth/freshness, scope, and action result.

  • Reduce Motion fixture and runtime capture
  • Reduce Transparency fixture and runtime capture
  • 200% content-size/zoom resilience where supported
  • VoiceOver reading-order snapshot
  • Focus remains stable when live state updates
  • Unresolved approvals cannot disappear through Escape or timed collapse

10. Phased implementation plan

Approval contract audit and fixtures

Files: AgentEvent.swift, BridgeTransport.swift, BridgeServer.swift, adapter-specific hook handlers, debug scenarios, focused tests.

  • Inventory Codex, Claude, OpenCode, and other supported-agent request and response semantics.
  • Write failing tests for correlation, idempotency, timeout/default-deny, stale request, adapter rejection, and scope preservation.
  • Define the normalized request/decision model without breaking provider-specific paths.
  • Add simultaneous-inbox, expired, rejected, and source-unavailable fixtures.

Exit: capability matrix exists and RED tests demonstrate missing unified behavior; no view changes.

Approval normalization and response broker

Files: OpenIslandCore approval contracts/projector, bridge routing, receipt actions, focused tests.

  • Normalize requests while retaining source payload ownership at the adapter.
  • Implement one decision per immutable request with idempotent delivery.
  • Track captured, delivered, acknowledged, rejected, expired, and unavailable states.
  • Emit content-free immutable receipts.

Exit: supported adapters acknowledge correct decisions and all failure paths fail closed.

Primary surface and approval inbox projection

Files: OpenIslandCore projector, AppModel types/projections, tests.

  • Implement one pure deterministic arbitration function.
  • Project one primary request and an ordered pending count without losing secondary requests.
  • Project active agent, task, explicit state verb, provenance, and unread result.
  • Keep session registries unchanged.

Exit: priority, multi-request, and degraded-state tests green.

Usage normalization

Files: usage domain model, Claude/Codex adapter wrappers, AppModel projection, tests.

  • Normalize existing snapshots without credentials.
  • Implement freshness and pressure policy.
  • Render unavailable rather than zero.

Exit: both current providers and unsupported-provider fixture pass.

Context headroom evidence

Files: extend OrbitContextBudget report/event, receipt action vocabulary, projections, tests.

  • Add event/provenance/confidence without content.
  • Expose retained/omitted tokens and decision.
  • Do not calculate money unless authoritative pricing is added later.

Exit: deterministic savings evidence and redaction-required paths pass.

Compact pill hierarchy

Files: closed-pill presentation and focused view tests.

  • Agent state first; one secondary pressure signal.
  • Explicit verbs and non-color symbols.
  • External display and physical-notch geometry preserved.

Exit: idle/running/attention/error/unread captures approved.

Expanded active-agent surface

Files: IslandPanelView decomposition into narrow components, approval/completion rows, usage/context strips.

  • One primary session; secondary sessions disclosed.
  • Approval scope and completion evidence redesigned.
  • Separate destructive power control from routine controls.

Exit: approval, question, completion, error, stale, unavailable captures approved.

Motion, accessibility, performance

Files: motion policy, accessibility labels/actions, harness, focused performance tests.

  • Interruptible transitions and hover/focus protection.
  • Reduced-effects variants.
  • VoiceOver and keyboard QA.
  • Bounded refresh and idle-resource audit.

Exit: accessibility and performance gates green.

Full-story verification and review

Run build, focused tests, full suite, docs, localization, security scan, deterministic runtime scenarios, artifact count, visual critique, and clean-worktree check. Commit each coherent slice separately.

Exit: all acceptance gates below have real evidence.

12. Rollback and failure recovery

  • Every phase is one focused branch/commit slice and can be reverted independently.
  • New projections sit above existing registries; if normalization fails, existing session behavior remains available.
  • Usage/context adapters are feature-gated and read-only. Disable the adapter rather than the agent integration.
  • Unsupported or failed sources render unavailable; no retry loop or credential prompt is introduced.
  • Preserve current compact/expanded fixtures as baseline comparisons until Plan v3 captures pass.
  • If performance regresses, disable decorative effects first, then lower refresh cadence; never disable approval correctness.
  • Never use destructive Git reset to recover; revert the focused commit or restore the feature flag.

13. Acceptance gates

  • A user identifies active agent, task, state, and required action within two seconds.
  • Priority order is deterministic and covered by tests.
  • Compact pill shows no more than one secondary usage/context pressure signal.
  • Expanded surface shows usage and context with truth, freshness, and provenance.
  • Unavailable data never appears as zero and stale data is visibly stale.
  • Context savings are token evidence with confidence; no unsupported dollar claim.
  • Approval shows requester, reason, scope, effects, and one-time semantics.
  • Allow/deny decisions are correlated, idempotent, delivered only to the origin adapter, and visibly acknowledged or rejected.
  • Multiple requests remain independently resolvable; timeout, cancellation, disconnect, and stale state never allow.
  • Completion persists as unread until reviewed or dismissed.
  • Keyboard, VoiceOver, Reduce Motion, Reduce Transparency, contrast, and focus gates pass.
  • No secrets or content leak into receipts, logs, fixtures, HTML, or screenshots.
  • Existing supported agents and terminal jump-back tests remain green.
  • Idle CPU/memory and refresh cadence remain within the existing all-day background budget.
  • Full build/tests/docs/localization/runtime scenarios pass with real artifacts.
  • Final defect-first and design critique find no unresolved critical issue.

14. Explicit non-goals

Not in Plan v3

  • Austin Router UI or subcommands
  • Slash-command palette
  • Skills/plugins/tools browser
  • New agent loop, shell, router, or provider-independent enforcement authority
  • Undocumented T3 Code integration or hard dependency
  • Provider credential storage or billing reconciliation
  • M4/M1 infrastructure or self-hosted Drive
  • Signing, notarization, deployment, or release

Clean-room limits

  • No Vibe Island code, assets, branding, binaries, or undocumented internals
  • No assumption that CodexBar/Headroom/T3 Code licenses permit direct reuse beyond documented intake
  • No removal of GPLv3 notices or upstream attribution
  • No claim of production readiness from local tests alone
